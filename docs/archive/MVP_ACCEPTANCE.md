SQLite 集成测试覆盖：

- 开书方案 → 人工确认 → 两章正式提交，第二章读取第一章事实。
- 重复命令幂等、同小说活动命令互斥。
- required 审核 MINOR 导致 FAIL，修复耗尽不提交、不跳章。
- 抽取失败保留正文候选，恢复后不重新生成已有正文。
- 进程恢复标记 INTERRUPTED，不自动调用模型；取消排队任务无调用。
- 提交事务中注入故障，事件、Delta、Snapshot、head、完成状态整体回滚。
- 第20章Checkpoint、第21章冷回放及重写后的父链隔离；旧支线保持可读。
- Checkpoint 哈希损坏时停止读取。
- Unicode 文本规范化、字数与规范化 JSON 哈希。
- 角色持有旧观察版本时，客观命题改变不自动改写 KNOWS。
- 非法状态结构、地点循环、Core策略禁用及缺失 required 结果阻断。

## 交付能力

1. 白色书架与三栏写作工作区，窄屏改为横向章节导航与上下布局。
2. 基于已确认Book和State 0滚动规划；前提逐章复查，有效窗口复用。
3. 正文生成、人工草稿、修复后的新候选版本、通用Evaluator结果、独立状态校验。
4. 唯一提交事务，同时推进正文和故事事实；Snapshot逐章元数据，每20章压缩Checkpoint。
5. SSE任务通知与持久化生成文本；预算、取消、重启恢复、显式增加额度。
6. 历史回退、后续退出有效链、候选保留、正式正文只读及TXT/Markdown导出。
7. 服务端ChatAnyWhere配置与分角色模型；独立管理后台的Skill及审核策略版本。

## 明确未验收或尚未实现

- **真实模型尚未验收**：没有配置真实 ChatAnyWhere 凭据。模型兼容性、供应商限额、文学质量、语义误判率及真实调用成本没有实测。
- 首版不是全部49项开发细则验收完成。未覆盖部分仍需在对应阶段补齐，不将18项测试等同为T01～T49全部通过。
- P5批次生产、P6参考作品/知识工作台与实体Registry、P7长篇检索优化、P8备份恢复/回收站均未交付。
- PromiseSchedule软期限管理与书级完结尚未提供；已支持的ChapterPlan.required Promise动作参与本章硬门禁。
- StateContextResolver当前保留完整基础事实与命题版本，避免在MVP阶段截断必要事实；大上下文会明确拒绝调用。尚未完成300/3000章规模及p95<2秒基准。
- 恢复复用正文候选，重新审核与抽取；更细粒度阶段复用、在途阶段换模型和批量恢复未实现。
- 后台和开书方案编辑使用严格校验的结构化JSON表单，尚未提供每类实体的专用可视化编辑器。
- 当前按普通单进程本机部署验收，未支持多实例服务或公网使用。

## 实施中修正

- Prisma生成的SQLite JSON默认值在本机导致SQL错误，改为由创建Job代码显式写空对象。
- Windows绝对SQLite路径需要预先存在文件；Prisma配置只创建缺失的空文件，所有表仍由正式migration建立。
- 修复多标签/页面切换的未保存草稿保护、审核侧栏的章节归属、冻结配置与Core门禁、引用未来事件阻断、服务端重新分配模型提案新身份。
- 按领域拆分事实回放与最终提交；Platform不负责事实转换。前端拆分页面、编辑器及侧栏组件。
- 编辑器初始化完成后才允许输入；切换只读状态不触发正文更新，避免初始化过程误触发自动保存。多标签页用例已回归通过。
- 开发启动直接调用Node入口，避免Windows IDE环境缺少System32 PATH时无法找到cmd.exe；关闭时仅结束本次启动的子进程树。
- npm下载异常使用官方原包和官方引擎重试，并核对完整性；最终lockfile保留正式npm依赖，不依赖`.cache`中的下载副本。
