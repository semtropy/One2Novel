# One2Novel · 本机小说写作

仅在本机运行的个人小说写作 Web 应用。从一句灵感出发，确认全书方向与初始事实，再逐章生成、审核和提交。旧代码、旧数据库与旧凭据均未导入。

本文只说明运行和已交付功能的用法。**当前进度、全部剩余工作与最新验收只看 [REMAINING_WORK.md](REMAINING_WORK.md)**；完整 V2 需求只看 [DEVELOPMENT_SPEC.md](DEVELOPMENT_SPEC.md)，开发约定见 [AGENTS.md](AGENTS.md)。完整 V2 尚未完成。

## 启动

需要 Node.js 24、pnpm 10。工作区已锁定依赖版本。

```powershell
pnpm install --frozen-lockfile
pnpm db:generate
pnpm db:migrate
pnpm dev
```

开发页面：<http://127.0.0.1:7457>。服务端：`127.0.0.1:7456`。

生产方式：

```powershell
pnpm build
pnpm start
```

生产页面：<http://127.0.0.1:7456>。所有数据位于根目录 `data/`，重启不会丢失。迁移只通过 `pnpm db:migrate` 执行，不在运行时补列。

## 配置模型

首次配置时，将 `.env.example` 复制为 `.env`，填写服务端 `CHATANYWHERE_API_KEY`，然后重启服务。密钥不在浏览器输入，也不写进数据库或 Git。设置 `ONE2NOVEL_DEFAULT_MODEL` 后，全新空库首次初始化会自动创建一个 `default` 模型档案并映射到所有角色；已有数据库配置不会被覆盖。

打开「模型设置」，添加实际可用的模型 ID，按供应商信息填写上下文、最大输出及支持的参数。默认所有角色可使用同一模型；「多模型与角色映射」支持分别配置规划、正文、审核、抽取和修复模型。

保存不会发送模型请求。「测试已保存配置」会执行一次显式连通测试。仅允许 ChatAnyWhere 的两个服务地址；没有其他供应商回退。没有密钥时应用仍可启动、创建项目和保存草稿，模型操作会明确提示未配置。

## 第一条创作流程

1. 新建小说，输入灵感、题材、目标字数和创作要求。
2. 生成开书方案，检查全书方向和开篇前事实。点击「编辑方案」，用中文表单调整概要、故事前提、核心问题、结局方向、分卷目标和角色介绍；逐项确认警告后启用设定。人物关系、认知等完整内容仍在「高级：完整设定与身份引用」中编辑。
3. 点击「生成本章」，后台依次规划、写作、审核、必要修复、提取事件、验证状态、原子提交。
4. 只有正式提交后才能「写下一章」。也可自行写草稿，点击「审核并提交草稿」进入相同门禁。
5. 从「版本」查看历史候选；重写已完成章节会先回退到前一章，后续旧正文退出当前事实链。旧版本保留可读。
6. 「导出」生成当前已提交章节的 Markdown；API 使用 `format=txt` 可导出纯文本。

第一章提交前，可在「全书与初始设定」修改并保存新候选，再确认重建开篇。保存候选不改变正式事实；确认时逐项核对全书前提，无法成立的前提需先修订。旧版本和草稿保留，旧生产任务失效。已有正文时，须先从第一章重写，再重建初始设定。

## 连续创作

确认开书方案且剩余至少两章时，工作区顶部提供「连续创作」。选择本批章数（2～10，不能超出目标范围）后，系统逐章规划、审核和原子提交。单章入口保持不变；人工工作草稿每次只审核一章。

- 「本章后暂停」等待当前已安排章节完成；尚未安排章节时立即暂停。暂停后可刷新、关闭页面，之后点「恢复任务」。
- 某章失败会暂停整个批次，不生成后文。恢复复用该章已有候选、冻结配置和累计计数，已提交章节不会重做。
- 每章初始预算为40次HTTP调用、正文修复2次、状态修复2次。「增加额度」只调整当前未完成章，不清零用量，不提高后续章节预算。
- 「取消任务」立即请求终止在途调用并停止后续章节；已提交章节保留。取消后的批次不能恢复，需要从当前进度新建命令。
- 暂停期间如果另一个命令推进或重写了故事，旧批次恢复会报输入过期。修改模型设置不会替换已冻结的批次配置。

进度面板显示已提交章数、当前章节阶段和累计调用次数。批次完成、达到目标章数都不自动标记全书完结。

任务等待处理时，面板展示卡住的阶段、原因和失败候选。可「查看失败候选」→「载入此候选到草稿」→修改→「审核并提交草稿」；也可「按当前输入重新生成」。这两种操作会结束旧任务并新建当前未完成章的任务，保留旧候选和用量，原批次不会自动续写。若只想重试原输入，先增加耗尽的额度，再「恢复任务」；批次恢复仍使用原子章，累计用量不清零。已修改的审核草稿、全书版本、知识绑定或引用授权不能套用旧任务恢复。

草稿自动保存并使用版本号防止多标签覆盖。未保存的本地输入暂存在当前浏览器会话中，刷新或切换章节后可恢复。版本冲突时保留本地输入，可先导出或明确重新保存。生成中断的文本可载入工作草稿，不能作为已审核正文直接提交。

服务重启不会自动继续调用模型；需在任务面板显式恢复。更换模型配置仅作用于新任务。

## 计划管理

确认开书后，在工作区打开“计划管理”。可查看全书、卷、剧情单元、章的已启用版本，编辑为新候选，再“校验并启用”；全书使用“确认全书更改并校验”。启用会调用模型，失败保留候选与旧活动计划。候选保存本身不调用模型，也不修改正式事实。

修改父计划会使依赖旧版本的后续计划重新规划，已完成章及其原计划保留。活动任务期间不能改计划；旧任务不能套用新计划恢复。可显示历史版本。当前编辑器采用结构化JSON，范围必须遵守父方向；同层范围调整需要尚未开始的完整父计划。独立按指定层生成、完整可视化表单仍未交付，进度以剩余清单为准。

## 独立配置后台

在 `.env` 设置 `ONE2NOVEL_ADMIN_TOKEN`，重启后直接访问 `/admin`。后台不出现在普通创作导航中。

可版本化配置 Skill 启停/强度/适用条件、required/optional 审核策略。可载入上一版本并保存为新版本。硬约束和状态一致性 Core 不可关闭或降低阈值。管理员会话一小时过期，服务重启后失效。

## 参考作品与知识库

顶部「参考与知识」进入 `/library`：

1. 导入 TXT（UTF-8 或 GB18030）或未加密 EPUB，最大20MiB。导入不调用模型，先预览原文和章节切分；可调整边界，再「确认并发布切分」。
2. 「开始完整分析」依次分析全部单元，显示覆盖字符数、实体与精确原文证据。失败可恢复，不重复已完成单元；同名歧义需先确认身份并创建新分析版本。
3. 完整后「发布分析版本」，提取叙事框架或原始素材。每次先生成候选，检查后「发布知识版本」。
4. 素材依次经过「原始 → 清洗 → 输入改编要求 → 改编」，每阶段发布后才能进入下一步。原始及清洗素材不能绑定小说。
5. 「新建风格」用中文表单填写视角、文字气质、对白百分比和禁用表达；「新建模板」填写章节目的与节奏、具体写作要求，也可选择全书/卷/剧情单元。保存后发布即可使用，无需编辑JSON。框架和素材默认显示可读卡片，高级结构编辑折叠收起。
6. 发布后的框架、改编素材、风格或模板可点击「用它开始新小说」，创建时自动应用所选资料。已有小说在工作区点击「创作知识」，选择已发布版本，再生成开书方案或继续创作。最多1份框架、3份改编素材、1份风格及每层级1份模板。活动任务期间不能改绑定。

知识进入实际规划和正文请求，不直接修改故事事实。发布新知识不改变旧绑定；修改绑定使旧任务和旧开书候选过期，需要创建新命令。原文件、全文、分析和知识版本均保存在SQLite。正文匹配参考原文连续80字符且未由用户授权来源引用，会被程序门禁拦截；引用授权须有已发布来源和精确原文，模型自行声明无效。该规则不能代替语义改编质量判断。

当前整体素材包或事实上下文超过模型窗口时会明确停止。可先编辑并发布清洗素材，排除不用的条目再改编。文学质量和真实模型长文能力需独立验收，不能由离线测试或一次连通测试推断。

## 检查

```powershell
pnpm typecheck
pnpm test
pnpm build
pnpm test:e2e
```

端到端测试默认使用本机 Chrome，独立监听 `7466`，使用临时 SQLite 与测试模型；生产入口没有 FakeModel 开关。可通过 `PLAYWRIGHT_CHANNEL=msedge` 使用 Edge。测试不会调用真实 API。开篇重建流程会调用 Python Playwright，需本机 Python 安装 `playwright` 包。

`python tests/e2e/browser_smoke.py` 可只读检查正在运行的生产页面（需要 Python Playwright）。`tests/e2e/recovery_flow.py` 是额外的人工解困浏览器流程，只能针对 `pnpm exec tsx tests/e2e/server.ts` 启动的隔离测试服务运行。

## 升级已有 V2 数据

本次计划版本功能新增迁移`20260909000000_plan_versions`（PlanVersion与项目planRevision），升级前需停止服务。已有待恢复任务缺少活动计划版本时应按当前输入新建任务；不会重写已提交正文或事实。

从已有MVP/P5升级时，先停止服务，执行 `pnpm db:generate`、`pnpm db:migrate`、`pnpm build`，再 `pnpm start`。P6增加参考/知识表，保留数据地重建Job表，使资料任务无需关联小说。父子任务、用量和事件保留。Prompt版本升至3；旧版本1/2未完成任务不会自动换Prompt续跑，需要从当前故事进度创建新命令。已提交正文和事实回放不受影响。

## 代码入口

- `apps/web/src/pages`：书架、工作区、模型设置与独立后台。
- `apps/web/src/features`：开书、编辑器、规划/审核/事实展示。
- `packages/contracts/src/index.ts`：严格 Zod 数据契约。
- `apps/server/src/orchestrator`：任务与跨领域编排、配置冻结。
- `apps/server/src/reference`：TXT/EPUB解析、实体检索、证据校验与身份确认。
- `apps/server/src/knowledge/library.ts`：知识派生、清洗/改编来源校验、版本和绑定。
- `apps/server/src/production/commit.ts`：唯一正式提交事务。
- `apps/server/src/story-state`：确定性 Delta 转换、校验与快照回放。
- `apps/server/src/platform/llm.ts`：统一 ChatAnyWhere 调用、超时、取消与计数。
- `apps/server/prisma/migrations`：从空数据库建立的正式迁移。

实现时核对了 [OpenAI JavaScript SDK 官方文档](https://developers.openai.com/api/reference/typescript) 与 [ChatAnyWhere 官方项目说明](https://github.com/chatanywhere/GPT_API_free)；SDK仅作为客户端，实际请求地址由 ChatAnyWhere 白名单限定。
